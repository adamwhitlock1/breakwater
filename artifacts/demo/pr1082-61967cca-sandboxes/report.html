  1. A1The fast‑path assumes that a version string containing only ASCII digits and dots is a simple numeric version, but it does not verify that the digits are ASCII.

    base: The original regex‐based parser only matches ASCII digits, so Version("１.２.３") raises InvalidVersion.; head: The fast‑path strips the string, splits on '.' and maps each part with `int()`, which accepts Unicode digits, so Version("１.２.３") succeeds and produces a Version with epoch=0, release=(1,2,3).

    Inputs: Unicode‑digit numeric versions without any PEP 440 indicator characters · e.g. Version("１.２.３") · Lightning strategies: 4/4 valid, 1 hits

  2. A2The fast‑path assumes that a version containing only ASCII digits and dots cannot have surrounding whitespace; it strips the whole string and therefore accepts versions with leading/trailing spaces that the PEP 440 regex would reject.

    base: Version(" 1.2.3 ") raises InvalidVersion because the PEP 440 regex does not allow whitespace.; head: Version(" 1.2.3 ") is accepted by the fast‑path, parsed as (1,2,3) and returns a Version object.

    Inputs: whitespace‑padded numeric versions · e.g. Version(" 1.2.3 "), Version("\t1.0\n") · Lightning strategies: 3/4 valid, 2 hits

  3. A3The fast‑path assumes a version string consists only of digits and dots, but it only checks a limited set of “non‑simple” characters and misses leading whitespace.

    base: Base `Version.__init__` runs the full PEP 440 regex on the original string (including whitespace). The regex fails, so `InvalidVersion` is raised.; head: Head’s fast‑path calls `version.strip()` before splitting on “.” and converting to ints, so leading/trailing whitespace is silently stripped and the version parses successfully.

    Inputs: simple numeric versions padded with leading/trailing whitespace · e.g. Version(" 1.2.3"), Version("\t1.2.3"), Version("\n1.2.3\n") · Lightning strategies: 4/4 valid, 0 hits

  4. A4The fast‑path assumes that surrounding whitespace is not part of the version string and strips it before parsing.

    base: The original regex uses ^…$ anchors and does not allow leading/trailing whitespace, so Version(" 1.2.3 ") raises InvalidVersion.; head: The fast‑path executes `version.strip().split('.')`, successfully parses the numbers and returns a valid Version object.

    Inputs: ASCII numeric versions with leading or trailing whitespace · e.g. Version(" 1.2.3 "), Version("\t2.0\n") · Lightning strategies: 3/4 valid, 1 hits

  5. A5The fast‑path only checks for the presence of ASCII letters and punctuation; it treats any other characters (including Unicode digits) as “simple” and parses each dot‑separated component with int(), which accepts Unicode decimal digits.

    base: Version("١.٢.٣") raises InvalidVersion because the PEP 440 regex only matches ASCII digits.; head: Version("١.٢.٣") passes the fast‑path, is parsed as (1,2,3) and returns a Version object.

    Inputs: Unicode‑digit numeric versions · e.g. Version("١.٢.٣"), Version("０.１.２") · Lightning strategies: 4/4 valid, 1 hits
